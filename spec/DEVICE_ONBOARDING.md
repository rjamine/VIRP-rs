# VIRP Device Onboarding — NetBox-Driven Workflow

## New Workflow (NetBox as source of truth)

### Adding a device

1. **Add device in NetBox** (UI at http://10.0.0.211:8081 or API)
   - Name: device hostname (e.g., `R36`)
   - Site: TLI-Lab-Home
   - Device Type: select appropriate (C7200, FortiGate 200G, etc.)
   - Role: Router, Firewall, Switch, etc.
   - Platform: Cisco IOS, FortiOS, PAN-OS, etc.
   - Status: Active
   - Custom fields:
     - `virp_enabled`: check if this is a VIRP-managed device
     - `virp_node_id`: hex node_id (e.g., `24242424` for R36)
   - Create a management interface (`mgmt0`, virtual) with the device's IP

2. **Add credentials** to `/run/virp/devices.json` (or the age-encrypted source)
   - This is the ONLY manual step — credentials never go in NetBox
   - Add the device entry with username/password/enable

3. **Sync** (automatic every 60s, or manual):
   ```bash
   # Preview changes
   virp-netbox-sync --once --dry-run

   # Apply
   virp-netbox-sync --once --pull
   ```

4. **Verify**:
   ```bash
   # Check generated configs
   python3 -c "import yaml; d=yaml.safe_load(open('/root/tli-ops-center/backend/config/devices.yaml')); print(len(d['devices']), 'devices')"

   # Check VIRP devices.json
   python3 -c "import json; d=json.load(open('/root/virp/devices.json')); print(len(d['devices']), 'VIRP devices')"
   ```

### Removing a device

1. Set device status to **Decommissioned** in NetBox
2. Wait for sync (or run `virp-netbox-sync --once`)
3. Device will be excluded from generated configs (only `active` devices sync)

### API example (adding a device via curl)

```bash
TOKEN="t0bsXfZl2DbbiHwcw3pJ0CQl2tEYvXxw9PSKoMbk"
NB="http://127.0.0.1:8081/api"

# Get required IDs

# Create device
curl -s -X POST -H "Authorization: Token $TOKEN" -H "Content-Type: application/json" \
  "$NB/dcim/devices/" -d "{
    \"name\": \"R36\",
    \"site\": $SITE,
    \"role\": $ROLE,
    \"device_type\": $DEVTYPE,
    \"platform\": $PLATFORM,
    \"status\": \"active\",
    \"custom_fields\": {
      \"virp_enabled\": true,
      \"virp_node_id\": \"24242424\"
    }
  }"
```

## Config Files Generated by Sync

| File | Content | Consumers |
|------|---------|-----------|
| `backend/config/devices.yaml` | Full device inventory with vendor/platform/roles | `device_registry.py` |
| `virp/devices.json` | VIRP-enabled devices with SSH creds and node_ids | O-Node (via age encryption) |
| `executor/config/devices.json` | All devices for C executor | C executor binary |
| `executor/config/pentest-scope.json` | In-scope hosts for pentest engine | C pentest engine |
| `/etc/virp/devices.json.age` | Age-encrypted VIRP devices | O-Node startup |

## Credentials

Credentials are stored ONLY in the age-encrypted `devices.json` at `/etc/virp/devices.json.age`, decrypted at O-Node startup to `/run/virp/devices.json`. They are NEVER stored in NetBox.

To add credentials for a new device, edit the runtime file and re-encrypt:
```bash
# Decrypt current
age -d -i /root/onode-key.txt /etc/virp/devices.json.age > /tmp/devices.json

# Edit (add new device entry)
vi /tmp/devices.json

# Re-encrypt
PUBKEY=$(age-keygen -y /root/onode-key.txt)
age -e -r "$PUBKEY" -o /etc/virp/devices.json.age /tmp/devices.json
rm /tmp/devices.json

# Restart O-Node to pick up new credentials
systemctl restart virp-onode
```
